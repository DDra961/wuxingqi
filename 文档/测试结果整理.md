### 5.1 BOSS 整体偏难，且不同 BOSS 差异大

## 6. 测试站位与幸运值

### 6.1 测试站位

1. 主角 → 队友1 → 队友2 依次布置。
2. 优先二环自己主属性节点。
3. 被敌人或已布置队友占用时，往下一环按格子 ID 逐个尝试所有位置。
4. 整环满则继续外环，最后用任意空格兜底。
5. 只决定开局位置；战斗内仍按固定策略移动。

实际游戏仍为求签后自由布阵，默认外环出生点被占用时自动找最近空格。测试站位更靠近敌人，因此会改变第 3 / 5 / 6 层和 BOSS 的承伤节奏。

### 6.2 幸运值

```
幸运 = 65 - 5 × 难度 + 宝剑加成
龙泉：+10
d = (幸运 - 35) / 5
```

求签权重：

| 签   |    权重 |
| ---- | ------: |
| 大吉 |  10 + d |
| 中吉 | 20 + 2d |
| 小吉 | 40 + 4d |
| 小凶 | 20 - 2d |
| 大凶 |  10 - d |

按总权重归一化，不保证总和为 100。战斗结算有 `幸运 / 2 %` 概率随机强化一个结算项：最大生命 +2→+4、攻击 +1→+2、随机宝物一件→两件，并在弹窗中高亮。

路线额外奇遇概率仍为：

```
p = clamp(0.5 + (幸运 - 40) × 0.005, 0.2, 0.85)
```

打怪后 `p × 0.5`，休息后 `p`；奇遇和 BOSS 节点不受影响。
本次模拟直接指定关卡且不执行求签/结算，所以幸运值不参与 2100 场战斗结果。

## 8. 全7 层顺序通关模拟

入口：`node 测试脚本/balance/run_campaign.mjs`
输出：`测试脚本/output/campaign_summary.md`、`campaign_results.csv`

口径：

- 固定难度 5。
- 5 主角属性 × 6 队友组合 × 2 个种子 × 每个种子 20 次 = **1200 轮**。
- 每轮先用「种子 + 层号」生成 7 层关卡，再按第 1~7 层顺序战斗。
- 第 1~6 层层号在 当前层 ±1 中随机并排除 0/7；第 7 层为 BOSS。
- 基础队伍，不带藏品 / 求签 / 结算 / 关外成长；每场资源重置。
- 失败立即停止该轮。
