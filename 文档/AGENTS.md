# AGENTS.md

## 项目概览

本地运行的 3D 五边形棋盘战棋肉鸽游戏。核心入口是单文件 `index.html`，配合本地 `app/server.py` 提供静态资源、关卡文件读写和生命周期管理。

当前阶段：计划7、计划8 已完成；进入计划9 QA。

## 启动方式

- 游戏：双击根目录 `启动游戏.bat`，或执行 `python app/server.py 8765`，打开 `http://127.0.0.1:8765/index.html`。
- 关卡编辑器：双击 `app/启动关卡编辑器.bat`。
- 不要直接双击 `index.html` 使用 `file://`；关卡、视频和保存接口都依赖本地服务。
- 服务会在页面关闭后自动退出；测试脚本可能自行启动/停止服务。

## 目录结构

- `index.html`：游戏本体，包含 Three.js 场景、战斗逻辑、肉鸽、存档、地图、视频背景。
- `玩法设计思路.txt`：玩法定位、核心循环、战斗与肉鸽设计取舍。
- `启动游戏.bat`：一键启动本地服务和游戏页面。
- `app/`：本地运行代码与工具。
  - `server.py`：本地静态服务、`/__health`、`/__save_level`、心跳与关服。
  - `three.module.js`：本地 Three.js 依赖。
  - `level_editor.html`：策划用 2D 关卡编辑器。
  - `启动关卡编辑器.bat`：启动服务并打开关卡编辑器。
- `关卡集/`：35 个关卡 JSON，按 `关卡{层}-{元素}.json` / `关卡7-{元素}boss.json` 命名。
- `测试脚本/`：自动化测试、数值模拟、关卡工具和输出结果。
- `美术资源/`：角色、名剑、背景、UI、结算动画等资源。
- `文档/`：规则、设计、进度、测试与美术文档。
  - `方案.txt`：规则、数值、进度与日志。
  - `规则书.md`：面向玩家的 1 分钟上手 + 5 分钟完整规则。
  - `AGENTS.md`：本文件。
  - `任务清单.md`、`美术开发.md`、`BOSS战.md`、`测试结果整理.md`、`个人记录.txt`。
- `logs/`：服务运行日志。
- `opencode.json`：opencode 项目配置（保留在根目录供工具读取）。
- `配置/`：工具补丁记录（`opencode.json.applied_patches`）。

## 不可破坏的规则

- 棋盘 51 格：1 / 5 / 10 / 15 / 20；五行区域与相克规则不要改。
- 主角团为「五选三」：主角固定，四名队友选二；当前队伍为 3 人。
- 共 7 层；第 1~6 层普通敌人每层成长 `CONFIG.scaling.layer = 0.1`。
- 第 1~6 层元素按「种子 + 层号」随机；层号在 `当前层 ±1` 中随机，排除 0 和 7。
- 第 7 层 BOSS 只按难度缩放；BOSS 基础值 `60 血 / 6 攻 / 6 防 / 0 体 / 12 魔 / 范围 3`；部位首击伤害为 `ceil(最大生命 / 8)`，60 血时为 8。
- 存档 key 为 `wuxing_run_v1`，当前版本 **v4**；不要破坏 v1~v3 兼容。
- 战斗每场资源回满；永久攻击/防御/上限保留；战斗内 buff 按快照恢复。
- 同格模型缩放为 `1.0 / 0.8 / 0.6 / 0.4`；保留进入顺序与纵向堆叠。
- 相机当前为 `position(0, 9.9, 6.9)`、`lookAt(0, 0.9, 1.0)`；调整时保留棋盘下移和低俯角。
- 背景视频使用 `美术资源/动态背景/video_1792407182426.mp4`，静态图作为 poster；渲染器保持透明背景。
- 右侧地图为 7 层纵向滚动画布；层号固定左侧；每层节点按数量居中：
  - 1 个：0.5
  - 2 个：0.33 / 0.67
  - 3 个：0.25 / 0.5 / 0.75
- 地图保留「同层同类节点合并」，但要画父节点到具体后继节点的连线。
- 选择弹窗底部不再放横向地图。

## 工作约束

- 不要一次全文读取 `index.html` 或 `文档/方案.txt`；先用 `grep` / `rg` 定位，再按范围读取。
- 一次只做一个可验收的改动；修改前先确认相关函数和当前状态。
- 不要在没有要求时重做数值、关卡或规则；美术任务只改表现层。
- 不要使用 UGC 或把美术资源入口暴露到玩家开始页。
- 修改逻辑后运行 `node 测试脚本/run_tests.mjs`。
- 不要主动提交 Git；当前目录尚未初始化 Git，改动前建议先做备份。
- 新增规则或数值时同步更新 `文档/方案.txt` 的对应章节和日志，不要只改代码。
- 新会话优先读取 `文档/AGENTS.md`、`文档/任务清单.md`、`文档/美术开发.md` 和 `文档/方案.txt` 的相关章节。

## 测试入口

```powershell
node 测试脚本/run_tests.mjs
node 测试脚本/balance/run_balance.mjs
node 测试脚本/balance/growth_sim.mjs
node 测试脚本/balance/run_campaign.mjs
```

测试输出在 `测试脚本/output/`。数值模拟是基础队伍、无藏品/求签/结算/关外成长的固定策略基线，不等同于真实通关率。

## 已知限制

- 数值模拟不模拟战后成长、求签和结算。
- BOSS 各元素难度差异较大，水 BOSS 对金/火主角偏难。
- 地图合并后存在多父节点共享后继，连线会交叉，需要继续观察可读性。
- 角色目前是程序化几何体，尚无 glTF 模型和动作系统。
